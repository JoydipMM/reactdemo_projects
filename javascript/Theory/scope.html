Type of scope in Javascript

JavaScript has several types of scope, determining the visibility and lifespan of variables. Here are the primary types:

These scoping rules help in structuring code and managing variable accessibility efficiently.

1. Global Scope

  • Variables declared outside any function or block are in the global scope. These variables are accessible from anywhere in the code, including inside functions and blocks.
  • In browsers, global variables are also added to the window object, meaning you can access them as window.variableName.
  • Excessive use of global variables can lead to potential naming conflicts and bugs, so it’s generally best to limit them.
var globalVar = "I am global"; // accessible anywhere
function example() {
    console.log(globalVar); // works fine
}
example();

2. Function Scope

  • Variables declared with var inside a function are scoped to that function only and cannot be accessed outside of it.
  • This type of scope applies only to variables declared with var (not let or const), which limits them to the function they are defined in. 
function myFunction() {
    var functionScopedVar = "I am function-scoped";
    console.log(functionScopedVar); // accessible within the function
}
console.log(functionScopedVar); // ReferenceError: functionScopedVar is not defined

3. Block Scope

  • Introduced with let and const in ES6, block scope applies to any variable declared within a block { }, such as within loops or if statements.
  • Block-scoped variables are only accessible within the block they are defined in.
if (true) {
    let blockScopedVar = "I am block-scoped";
    console.log(blockScopedVar); // accessible here
}
console.log(blockScopedVar); // ReferenceError: blockScopedVar is not defined

4. Module Scope

  • Variables declared inside a JavaScript module are only available within that module, effectively making each module its own scope.
  • This type of scope is enabled by using the export and import syntax.
  • Module-scoped variables are not added to the global scope, reducing conflicts in large codebases.
// module.js
const moduleScopedVar = "I am module-scoped";
export function test() {
    console.log(moduleScopedVar); // accessible within the module
}

// main.js
import { test } from './module.js';
console.log(moduleScopedVar); // ReferenceError: moduleScopedVar is not defined

5. Lexical Scope (or Closure Scope)

  • Lexical scope refers to the fact that inner functions have access to variables in their outer functions' scopes due to JavaScript's closure behavior.
  • Closures allow functions to "remember" the scope they were defined in, which means they have access to their outer environment variables even when executed outside their original scope.
function outer() {
    const outerVar = "I am outer";
    function inner() {
        console.log(outerVar); // can access outerVar due to closure
    }
    return inner;
}
const innerFunc = outer();
innerFunc(); // logs: "I am outer"
