Path Module

The Path module is a built-in Node.js module that helps you work with file and directory paths. It provides utilities to create, manipulate, normalize, and resolve file paths in a way that works across different operating systems. Since it's a built-in module, you don't need to install it.

Use of Path Module


path.resolve()

path.resolve() is a method of Node.js's built-in path module. It converts a sequence of path segments into an absolute path.

Syntax

  • Accepts zero or more path segments.
  • Processes the paths from right to left.
  • Stops when it encounters an absolute path.
  • If no absolute path is found, it uses the current working directory (process.cwd()).

Importing the Path Module


When should you use path.resolve()?

Use path.resolve() when you need an absolute path, such as when:

  • Reading or writing files with the fs module.
  • Configuring file uploads.
  • Serving static assets in web servers.
  • Building reliable paths that don't depend on where a script is called from.

Summary

  • path.resolve() always returns an absolute path.
  • It resolves . (current directory) and .. (parent directory).
  • It processes path segments from right to left and stops when it finds an absolute path.
  • If no absolute path is provided, it starts from the current working directory (process.cwd()).

Event Emitter

EventEmitter is a built-in class in Node.js that allows objects to emit (trigger) events and listen for those events. It is the foundation of Node.js's event-driven architecture.

  • Emitter → Announces that something happened.
  • Listener → Waits for that event and responds to it.

Why do we need EventEmitter?

Without EventEmitter everything is tightly coupled. Take the below taskCompleted() function as an example. Here we have 3 functions that are tightly coupled. So when taskCompleted() is called, all 3 functions are called. There is no way to call indivitual functions separately. So to solve this problem we use EventEmitter, which allows us to call individual functions separately with independent listeners

Code explanation:

What is origin?

origin is automatically sent by the browser in the HTTP request. Suppose our API is http://localhost:5000. If your React app runs on http://localhost:3000, then origin will be http://localhost:3000.

Why !origin?

Some requests don't have an Origin header. like Postman, curl, server-to-server requests, some mobile apps, same-origin requests in certain situations. In those cases, origin will be undefined, then !origin will return true. So we can say that "If no Origin header exists, allow the request."

What is allowedOrigins?

This is simply a whitelist. Only these websites can access your API.

At present only these websites can access our API and only these three origins are allowed.

What does allowedOrigins.indexOf(origin) do?

allowedOrigins is an array of whitelisted URLs (origins) that are permitted to access the API through CORS.

indexOf(origin) searches the allowedOrigins whitelist array for the origin received from the browser and returns its index if found; otherwise, it returns -1

  • Senario 1

    Here allowedOrigins.indexOf(origin) will return 0. because it is found at index 0.

  • Senario 2

    Suppose our origin is "https://google.com"

    But our allowedOrigins is ["http://localhost:3000"]. So it will return -1, because it doesn't exist.

Why use OR (||)?

The condition is !origin || allowedOrigins.indexOf(origin) !== -1 It means allow the request if either:

  • there is no Origin header, OR

  • the Origin is present in the whitelist.

!== -1 means The value is not equal to -1

Some Senarios:

  • Scenario 1 (React App): origin is http://localhost:3000

    !origin means No Origin header exists then it return true

    But here we get origin from React App http://localhost:3000.

    That means origin exists. Then ***!origin will return false

    allowedOrigins = ["http://localhost:3000"] means that in allowedOrigins array list at index of 0 http://localhost:3000 url found and React app can access our API

    allowedOrigins.indexOf(origin) will return 0

    So, 0 !== -1 will return true because 0 is not equal to -1

  • Scenario 2 (Postman): Origin: undefined

    Then !origin will return true

    So, when it get true from !origin, it will return callback(null, true). That means Allow the request and it will not check allowedOrigins.indexOf(origin)

  • Scenario 3 (Unknown Website): Origin: http://unknownwebsite.com

    Here !origin will return false

    So, when it get false from !origin, it will check allowedOrigins.indexOf(origin). Here also allowedOrigins.indexOf(origin) will return -1. So -1 !== -1 will return false. That means Deny the request

    0 !== -1 means 0 is not equal to -1 so this is true

    -1 !== -1 means -1 is not equal to -1 so this is false

Redis in Node.js

Radis is a key-value store that is used to store data in memory.

Full form of Redis is: Remote Dictionary Server.

Redis is an in-memory data store that is most commonly used as a cache, but it can also work as a database, message broker, and session store.

Think of it this way:

  • MySQL / PostgreSQL / MongoDB → Store data permanently on disk.
  • Redis → Stores data primarily in RAM (memory), making it extremely fast.
