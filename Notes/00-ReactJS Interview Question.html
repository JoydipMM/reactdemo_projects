What is React.js?

React is a JavaScript library for building interactive user interfaces using reusable components. It follows a declarative programming approach, where developers describe the desired UI, and React manages the necessary DOM updates when application data changes.

It was originally developed by Facebook (now Meta) and is maintained by Meta and the React community. React allows developers to build applications using reusable, independent components.

React.memo() Hook

React.memo() is a higher-order component (HOC) in React that optimizes performance by memoizing a functional component. It prevents the component from re-rendering due to its parent's re-render when its props have not changed. React compares the previous and new props using shallow comparison and skips the parent-driven render if they are equal.

Example without React.memo

First We create Three components. 1.ReRenderHook.jsx ( Parent Component ) 2.ReRenderHookChildOne.jsx ( Child Component ) 3.ReRenderHookChildTwo.jsx ( Child Component )

Console Output:

When the user clicks the Click button:

  • The count state in the parent component (ReRenderHook) is updated using setCount().
  • Updating the state triggers a re-render of the parent component.
  • During the parent's re-render, React also re-renders both child components (ReRenderHookChildOne and ReRenderHookChildTwo), even though they do not receive any props and their own state has not changed.
  • This happens because the child components are not memoized using React.memo().

Simple way: Whenever the user clicks the button, the parent component's state (count) is updated, triggering a re-render of the parent component. Since React.memo() is not used, both child components also re-render, even though they do not receive any props and their internal state has not changed.

Re-rendering a component does not necessarily mean React updates the actual DOM. React may re-render components, compare the resulting elements through reconciliation, and update only the DOM elements that require changes. This behavior occurs on every click of the button.

React follows a default rendering behavior:

  • When a component's state changes, React schedules that component for re-rendering.
  • When the parent component re-renders, React normally re-renders its child components as well.
  • React does not automatically skip rendering a child component just because its props have not changed.
  • React.memo() can help prevent unnecessary child component re-renders when their props remain unchanged.

useMemo Hook

useMemo is a React Hook that memoizes the result of a calculation and returns the cached value between renders as long as its dependencies remain unchanged. When any dependency changes, React recalculates the value and stores the updated result.

Memoizes (Verb)

Memoizes means stores or caches a result so that it can be reused later instead of calculating it again.

Memoization (Noun)

Memoization is a programming optimization technique in which the result of a calculation or function is cached and reused when the same inputs are provided.

Easy way to remember
  • Memoization = The technique.
  • Memoizes = The action.
  • Memoized = The cached result.

"useMemo() uses memoization to cache the result of a calculation and reuse the memoized value between renders when its dependencies haven't changed."

Understanding the Dependency Array in useCallback() Hook

The dependency array determines when React should return a new function reference.

Let's understand three scenarios:
01. Empty Dependency Array []:

The function reference remains the same across re-renders.

02. Dependency Array with Values:
  • If count doesn't change, React returns the previous function reference.
  • If count changes, React returns a new function reference and child component re-render.
03. Without Dependency Array:

Without a dependency array, React returns a new function on every render. Therefore, there is no memoization benefit.


How useCallback Works Internally (Conceptually)

Consider:

Think of the process like this:

First Render:
  1. React creates the function.
  2. React stores its reference.
  3. React returns that function reference.
Second Render:
  1. React checks the dependency array.
  2. React compares the previous dependencies with the new dependencies.
  3. Since the dependencies haven't changed, React returns the previous function reference.
Third Render:

The same process continues till the dependencies have changed

Quick Recap

useCallback

useMemo

Memoizes the calculated result.

React.memo

Prevents unnecessary component re-renders when its props remain unchanged.

Does useCallback prevent component re-rendering?

No. useCallback does not prevent component re-rendering. It maintains a stable function reference, "which can help prevent unnecessary child component re-renders when combined with React.memo".

Can useCallback work without React.memo?

Yes. It can also be useful when a function is used as a dependency of another Hook, such as useEffect. However, simply using useCallback does not prevent child component re-renders.

Without useCallback() every time the component re-renders, JavaScript creates a new function reference. So for the dependency array React compares the previous and current getUsers references. Since the reference changes on every render, React considers the dependency changed.

Execution flow:

With useCallback() React compares the previous and current getUsers references. Since the reference hasn't changed, useEffect doesn't execute again.

Note:

Do we always need useCallback here?

Not necessarily. If getUsers is only used inside useEffect, we can simply define the function inside the effect. This is often the simpler and preferred approach.

useReducer Hook in React

The useReducer Hook is a React Hook used to manage complex state logic in functional components.

It is an alternative to useState. Instead of updating state directly using a setter function, useReducer updates state through a reducer function and dispatched actions.

It is particularly useful when:

  • A component has multiple related state values.
  • State updates involve complex conditions.
  • Multiple actions modify the same state.
  • You want to keep state update logic in one centralized place.

Syntax of useReducer:

parameter description
  • state: Current state value.
  • dispatch: Function used to send an action to the reducer.
  • reducer: Function that determines how the state should be updated.
  • initialState: Initial value of the state.

Syntax of reducer function:

parameter description
  • state: Current state.
  • action: An object describing what should happen.
  • return: The updated state.

Syntax of dispatch:

parameter description
  • type: Specifies which action should execute.
  • payload: Optional data passed to the reducer.
