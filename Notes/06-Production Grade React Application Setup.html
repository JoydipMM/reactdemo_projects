Step 01 : Create .env file, where we will store our API access token if any


Step 02 : Create src/shared/utils/constants.js file, where we will store our API base URL and other constants


Step 03 : Create src/shared/api/client.ts file, where we will create axios instance

Note: Why use instance?
  • Cleaner code
  • Centralized headers
  • Easier auth handling
  • Easier interceptors
Difference Between Accept and Content-Type:
  • Accept: [send JSON] What response format client wants
  • Content-Type: [receive JSON] What request body format client sends
Other Common Headers:
  • Authorization: Used to send credentials (e.g., Bearer token) for authentication.
  • Accept-Language: Preferred language.
  • Cache-Control: Used to specify caching behavior (e.g., no-cache, no-store).
  • Multipart/FormData: For image upload:
  • User-Agent: Identifies the client software making the request.
  • Accept-Encoding: Specifies the content encoding (e.g., gzip) the client can handle.
  • Origin: Indicates the origin of the request, used in cross-origin requests.
Important Axios Behavior
  • Usually no Content-Type needed for GET Request because no request body is sent.
  • POST/PUT/PATCH Usually need: 'Content-Type': 'application/json'

Best Practice of Axios Usage
DO DON'T
✅ Create single axios instance
✅ Use service layer
✅ Use interceptors
✅ Use TypeScript types
✅ Use React Query/TanStack Query with Axios
✅ Centralize API logic
✅ Handle loading/error globally
 ❌ Call axios directly everywhere
❌ Store API URLs in components
❌ Repeat headers repeatedly
❌ Ignore cancellation/cleanup
❌ Mix UI and API logic

Axios + TanStack Query is the current industry standard combination.
