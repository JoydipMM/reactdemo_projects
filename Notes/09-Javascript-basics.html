Different between var, let and const

var : was the original way to declare variables before ES6.

Characteristics

  • Function-scoped (not block-scoped)
  • Can be redeclared and reassigned
  • Gets hoisted and initialized with undefined

let : Introduced in ES6. It is block-scoped.

Characteristics

  • Block-scoped
  • Can be reassigned
  • Cannot be redeclared in the same scope
  • Hoisted but placed in the Temporal Dead Zone (TDZ). The variable exists but cannot be accessed before declaration.

const : was the original way to declare variables before ES6.

Characteristics

  • Block-scoped
  • Cannot be reassigned
  • Cannot be redeclared
  • Must be initialized during declaration
  • Hoisted but in the TDZ

callback hell in JavaScript

Callback Hell is a situation where multiple asynchronous operations are nested inside one another using callbacks, making the code difficult to read, understand, and maintain. This is also known as the "Pyramid of Doom" because the code keeps shifting to the right.


Example: Suppose you want to perform these tasks in order:
  1. Login user
  2. Fetch user profile
  3. Fetch user posts
  4. Display posts

Why is it called the "Pyramid of Doom"?

As more asynchronous operations are added, the nesting grows the code starts looking like a pyramid.

Problems with Callback Hell

  • Hard to read and maintain
  • Difficult to debug
  • Difficult to maintain
  • Error handling becomes complicated
  • Code becomes deeply nested

Promise in javaScript

A Promise is an object that represents the eventual completion (or failure) of an asynchronous operation and its resulting value.

A Promise is a JavaScript object used to handle asynchronous operations. It represents a value that may be available now, in the future, or never. A Promise can be in one of three states: Pending, Fulfilled, or Rejected, and it helps avoid callback hell by providing cleaner asynchronous code through .then(), .catch(), and async/await.


Creating a Promise

  1. resolve() → Marks the promise as successful.
  2. reject() → Marks the promise as failed.

Important Note:

resolve and reject are functions provided automatically by the Promise constructor. Calling resolve(value) fulfills the Promise with a value, while calling reject(reason) rejects the Promise with an error or reason. They are not objects, and they are passed as arguments to the Promise's executor function.

When we write new Promise the JavaScript engine automatically passes two functions to the executor function. We can think of it like this


What does resolve() and reject() do?

Calling resolve() changes the Promise's state from Pending to Fulfilled.

Calling reject() changes the Promise's state from Pending to Rejected.


Can we name them anything else?

Yes. They are just function parameters. If we change the name of them, these work exactly the same, but using resolve and reject is the standard convention because it makes the code easier to understand.
Promise States

A Promise can be in one of three states:

  1. Pending → Initial state, operation is still running.
  2. Fulfilled (Resolved) → Operation completed successfully.
  3. Rejected → Operation failed.

Javascript code execution flow difference between async/await and promise chaining

When we try to get data from promise using promise chaining, the code execution flow is not blocked. So the console.log("promiseChainingFn run completed") line will be executed first and then after 5 seconds the promise will be resolved and then we get the data from promise.


But when we try to get data from promise using async/await, the asyncAwaitFn() execution is suspended because javaScript found that the promise is not yet resolved. So the call stack is empty until the promise is resolved after 5 seconds. After 5 second when the promise is resolved asyncAwaitFn() again called and asyncAwaitFn() again come to call stack and start executing but this time it will start from the first console.log("common promise resolved after 5 seconds") line. Now javaScript log the value and reach to next line where another await is waiting for execution, JavaScript try to find that the promise is resolved or not. If this promise not yet resolved because this promise will resolved after 10 seconds, So it will again suspend the execution and call Stack again empty. once the second promise is resolved after 10 seconds, again asyncAwaitFn() come to call stack and again executing from the next line of second promise and log the value of second promise. This is how the total execution flow of async/await work.


If we use two promises, the second promise will be executed only after the first promise is resolved

Promise APIs
  • Promise.all() → Waits for all promises to succeed. The output of Promise.all() will be an array with the results of all promises. Maximum time of any of the promises will be the time taken by Promise.all(). It will wait for all promises to resolve, it will collect the results and return them as an array. Means if one promise takes 5 seconds, second promise takes 3 seconds, then Promise.all() will take 5 seconds. All of this will happen if all promises are successful.
    If any of the promises fails, then as soon as any of the promises is rejected, Promise.all() throw an error immediately. As example, if one promise takes 5 seconds, second promise takes 3 seconds, and the second promise fails, then Promise.all() will take 3 seconds and throw an error. It will not wait for the first promise and third promise to resolve. It will throw an error immediately after the second promise is rejected.
    Resolved rejected
  • Promise.allSettled() → same as Promise.all() but it little bit different when one of the promises is rejected. It will Waits for all promises to settle (either resolve or reject) and returns an array of their results.
    Resolved rejected
  • Promise.race() → Resolves or rejects as soon as one promise resolves or rejects. Suppose we have three promises, first promise will take 5 seconds, second promise will take 3 seconds, and third promise will take 10 seconds. Then Promise.race() will take 3 seconds and resolve. As soon as any of the promises is settled first, Promise.race() will give the result of that promise. This will happen if all promise are successfull.
    If any of the promises get settled first with rejection, then Promise.race() will throw an error immediately
    Resolved rejected
  • Promise.any() [ Success seeking APIs ] → It also takes list of promises and waits for any of promise to get first success / resolve and returns the value of that resolved promise. If any of the promise is rejected first, then nothing will happen after rejected. Promise.any() will wait for the first promise to success/resolve. Now if all the promises are rejected, then Promise.any() will throw an AggregateError. This AggregateError will be an array of all the rejected promises error.
    Resolved rejected

Note:

For all these Promise APIs, all promises called in parallel.
